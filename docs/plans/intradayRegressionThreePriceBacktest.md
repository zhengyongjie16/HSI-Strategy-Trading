# intradayRegression 三价探测回测初步设计

## 1. 状态与目标

状态：三价探测、延迟离散及监控标的参考收益规则已确认，本文为初步实施设计；本次仅修改设计文档，不修改实盘策略。延迟柱数采用 `max(1, ceil(delaySeconds / 60))`。

目标：使用历史一分钟 K 线，为 intradayRegression 构建可重复、可审计的离线近似回测。每分钟使用最近 200 根 K 线，当前柱分别以 H、L、C 为试算价格评估信号；延迟候选仅由后续指定分钟的收盘指标验证。首期同时统计监控标的虚拟多空操作的参考收益率，不统计具体轮证收益。

本方案不需要 setOnTrades，也不假设能够从分钟 OHLCV 恢复真实逐笔路径。它是新定义的回测模型，不等价于当前实盘事件回放。

## 2. 已明确的需求

1. 依次处理目标交易日的一分钟 K 线。
2. 对当前柱 B[i]，窗口由此前 199 根历史柱与 B[i] 组成。
3. 当日历史柱不足时向前取先前交易日数据；此前数据仅用于预热，不产生目标交易日之前的候选。
4. 当前柱以最高价、最低价、收盘价分别计算指标，任一试算满足某动作规则则可产生该动作候选。
5. 三价触发均归属于当前分钟，不推测高低价发生的秒级时刻。
6. 延迟候选在目标后续柱的收盘指标上验证，不使用实盘目标时刻、+5 秒、+10 秒三个样本，也不额外等待 10 秒。
7. 延迟柱数按 `max(1, ceil(delaySeconds / 60))` 计算：1~~60 秒为 1 柱，61~~120 秒为 2 柱，121~180 秒为 3 柱；无延迟验证配置仍立即输出。

## 3. 源码核查

- `src/core/strategy/intradayRegression/config.json`：当前买入验证为 60 秒、D 与 ADX；卖出验证为 60 秒、K。
- `src/core/strategy/intradayRegression/runtime/index.ts`：已提交指标基线与活动柱 preview 分离；同柱更新不会重复累计活动柱。
- `src/core/strategy/intradayRegression/runtime/mfi.ts`：MFI 使用 `(high + low + close) / 3 * volume`，不只是 close。
- `src/core/strategy/intradayRegression/utils.ts`：可复用条件组求值、指标有效性检查以及延迟/立即模式判断。
- `src/core/strategy/intradayRegression/verification/index.ts`：实盘使用三个最近样本；ADX 始终要求下降，其余指标按动作方向比较，等值不通过。
- `src/core/strategy/intradayRegression/index.ts`：候选生成还依赖席位与卖出初始买单事实，且内部绑定实盘采样和定时器。
- `src/main/businessEventProgram/index.ts`：实盘具有 latest-only 合并与观察时间语义，不适合作为本离散模型的直接驱动器。

重要区别：实盘缓存保留 200 根，不意味着每次从最近 200 根重新初始化所有递归指标。实盘 runtime 正常增量推进时，EMA、RSI 平滑状态、KDJ、ADX 等可能保留更早历史的影响。用户要求的严格滚动 200 根模型应每个窗口独立重算，不得宣称与实盘增量模型完全一致。

## 4. 业务决策与时段边界

### 4.1 OHLCV 试算字段

历史 199 根保留真实 OHLCV；当前柱的 O/H/L/V 保持历史值，仅将 close 分别替换为 H、L、C。

即：

- H 分支：`{ ...B[i], close: B[i].high }`
- L 分支：`{ ...B[i], close: B[i].low }`
- C 分支：原始 `B[i]`

“历史柱使用收盘价”解释为历史柱已最终收线，不解释为把历史柱 O/H/L 全部改成 C。将其平坦化会改变 KDJ、MFI、ADX 的数学输入，因此不采用。

### 4.2 多个分支同时满足同一动作

同一动作同一分钟只登记一个候选，使用固定 H → L → C 优先级选择首个可登记分支的初始指标；L/C 分支的额外命中仍写入审计，但不再登记重复候选。

禁止查看后续验证结果后再挑选最有利的初始分支。H/L/C 优先级只代表确定性回测规则，不代表真实成交先后。

### 4.3 延迟与交易时段（延迟离散规则已确认）

只有 `needsDelayedVerification` 为真时，`delayBars = max(1, ceil(delaySeconds / 60))`。

示例：1、59、60 秒 → 1 柱；61、119、120 秒 → 2 柱；121、179、180 秒 → 3 柱。零延迟或无验证指标依照现有规则立即输出，而非强制等待一柱。

还需决定“下一柱”是否允许跨午休。建议交易时段结束时清理 pending，与实盘连续交易时段失效语义保持一致；历史预热窗口仍允许跨午休及交易日。目标区间内意外缺失数据不可静默将验证顺延到更晚的可用柱。

### 4.4 首期范围

首期包含信号、候选、验证、监控标的虚拟持仓及参考收益报告。

- BUYCALL 开多或加多，SELLCALL 平掉全部同侧多仓。
- BUYPUT 开空或加空，SELLPUT 平掉全部同侧空仓。
- 多空按独立方向记账，平一侧不影响另一侧，不自动反手。
- 每次开仓采用等额名义资金，允许同侧逐次加仓。
- 使用决策所在柱收盘价作为虚拟开平仓参考价，日末按最后有效分钟柱 C 统一结算，次日空仓开始。
- 卖出候选首次评估时要求对应方向已有虚拟持仓；验证通过后再按当时实际剩余虚拟持仓平仓，无仓时只记录跳过。

收益是监控标的方向性参考收益，不是轮证收益或真实券商账户收益。即使监控标的是不可直接交易的指数，也可以按此定义计算价格参考收益。详见第 14 节。

## 5. 可行性与合理性判断

工程上可行。200 根 × 每分钟 3 次试算的计算规模适合首期直接复用指标函数重算，不需要逐笔数据库或通用虚拟交易所。

适合作为：

- 收盘策略之外的三价条件探测研究；
- 相同数据、窗口和规则下的可重复参数比较；
- 分钟级延迟验证研究；
- 与 close-only 基准对比，量化 H/L 探测带来的额外候选。

不适合作为：

- 当前实盘实时 K 线策略的精确复现；
- 真实逐笔触发次数或成交顺序证明；
- 仅凭监控行情计算真实轮证收益；
- 理论上的最好/最差收益边界。

三价并不能覆盖所有可能的盘中指标组合；条件组非单调、部分指标依赖 H/L/V，不能声称“所有盘中信号都能检出”。

## 6. 信息可用性与偏差

H/L/C 试算使用当前柱最终 H/L/V，最高价发生时可能尚不知道最终最低价及全分钟成交量。该模型必须定义为收线后的假设性探测，不能假装当时已观察到这些数据。

记录两个不同时间：

- `originBarTimestamp`：候选所属分钟。
- `decisionAvailableAt`：完整当前柱或验证目标柱收线后，模型才可获得决策。

用户确认使用决策所在柱 C 作为参考记账价格：立即信号使用触发柱 C，延迟信号使用验证通过柱 C。H/L 只影响指标探测和候选初始值，不能作为开平仓价格。决策发生在收线后，以该收盘价做假设性记账，不声称已知收盘结果后仍能在真实市场按此价格成交，也不将盈亏归入决策可用时间之前。报告须标明同柱收盘参考价假设。

“任一分支满足”扩大了触发集合，且单点验证比实盘三点验证不同，存在偏乐观风险，但收益偏差方向不保证恒定。应同时报告 close-only 对照。

## 7. 拟定逐分钟算法

以下流程在第 4 节决策确认后定稿。

1. 读取目标交易日、交易日历与足够的前置 OHLCV；严格校验时间顺序、重复、会话和缺口。
2. 对 B[i] 取得此前 199 根真实历史柱；不足时向更早交易日补齐。首期严格模式无法凑齐时拒绝该区段回测，不自动缩短窗口。
3. 分别构造 H/L/C 三个完整 200 根窗口；每个窗口独立初始化指标并生成快照。
4. 先对进入当前柱之前已存在且在当前柱到期的 pending，使用当前 C 快照验证并终态化。
5. 对三价快照分别调用相同 DSL 条件求值，再按确定的合并规则生成当前分钟候选。
6. 立即模式输出当前柱信号；延迟模式保存触发分支对应的初始验证指标、目标柱身份和候选身份。
7. 将本柱验证通过与立即输出的动作按第 14 节的同柱顺序记入虚拟持仓账本，参考价统一为本柱 C。
8. 推进下一分钟时只保存当前真实收线 OHLCV；不得把 H/L 试算结果作为新的历史柱，也不得一次累计三根。
9. 按确定的交易时段门禁清理到期未验证或已失效候选；日末禁止新开仓、结算剩余虚拟持仓并输出每日参考收益。

本柱生成新候选使用进入本柱时的持仓快照做卖出初始授权；先收集全部动作，再统一记账，避免本柱刚建立的虚拟持仓反过来授权同柱卖出候选。

同一分支必须独立满足完整条件组，不得把 H 分支满足的 RSI 与 L 分支满足的 MFI 拼成一次 `/N` 条件成立。

不同分钟生成的同动作候选允许各自存在；不要因为已有 pending 就阻止后续分钟候选。每条候选用自身初始指标验证，而非使用后来更新的初始值。

## 8. 验证比较规则

沿用 intradayRegression 的比较方向，但采样规则采用本模型指定的单一目标收盘快照。

- BUYCALL、SELLPUT：所有非 ADX 验证指标严格高于该候选初始值。
- BUYPUT、SELLCALL：所有非 ADX 验证指标严格低于该候选初始值。
- ADX：所有动作都要求严格低于初始值。
- 任一必要指标缺失、无效或等于初始值，均不通过。
- 不要求目标柱再次满足原始信号阈值，除非后续明确变更需求。
- 不使用最近样本搜索、不复制一份样本伪装实盘三点验证、不使用原有秒级 timer。

建议首期专用目录 `src/backtest/intradayRegression/`，不建设通用 tick 回放平台。

若需要复用验证比较，仅提取实际共享的纯比较规则；不为一个回测模型改造全局调度器，也不复制整套指标公式。

首期虚拟持仓账本仅服务监控标的参考收益，不实现券商订单撮合，也不声称覆盖生产订单状态机、智能平仓、保护性清仓和自动换标。

## 10. 审计与结果

每次运行保存：数据来源与校验摘要、数据内容哈希、代码版本、策略配置快照、窗口长度、三价字段语义、候选合并规则、延迟离散规则、时段边界规则、时区与复权口径。

每条候选保存：所属分钟、action、触发分支、三个分支命中情况、所命中条件组、初始指标、目标柱、目标 C 指标、验证通过/失败/失效原因、决策可用时间。

基础报告输出：每日各动作条件命中数、延迟登记数、验证通过数、指标缺失数、时段失效数、H/L-only 额外候选数及 close-only 对照。

收益报告输出：每笔虚拟开仓批次与退出原因、开平仓参考价、投入名义资金、方向收益率、虚拟盈亏、每日及全区间多头/空头/合计投入名义资金加权收益率。所有结果标明监控标的、毛收益、同柱收盘参考价模型。

未定义初始账户资金和融资约束，因此不输出账户复合累计收益率或账户百分比最大回撤；全区间收益按第 14 节投入加权计算，不能把每日收益简单相加或复利连乘。

## 11. 关键验收检查

1. H/L/C 全相同时，结果与 close-only 一致，不产生三次重复动作。
2. H 或 L 独有命中可被探测，且下一分钟历史状态仍使用真实 C。
3. 三个分支不共享可变指标状态，调整计算顺序不改变各自数值。
4. 每一窗口与现有指标函数对该确切 200 根数据的独立重算一致。
5. 不跨分支拼接 N-of-M 条件。
6. 多分支命中的初始值与确定后的合并规则一致。
7. 0、1、59、60、119、120、179、180 秒及无验证指标配置符合确定规则。
8. 使用目标柱自身最近 200 根窗口的 C 指标验证，不使用发起时的旧窗口或目标 H/L。
9. ADX 特殊方向、严格不等、缺失拒绝得到直接测试。
10. 午休、半日市、日末、历史预热和数据缺口有明确结果，不静默顺延。
11. 改变验证目标之后的数据不会改变此前候选及验证结果；信号绝不在 `decisionAvailableAt` 之前成交。
12. 相同输入与配置输出稳定一致；只有未来实际修改 TypeScript 时才运行格式化、lint、类型检查和相关测试。
13. 多空收益符号正确；相同开平价格收益为零；H/L 命中仍使用 C 记账。
14. 多笔等额加仓后，同侧卖出全部结算；平仓数量、批次数与名义投入一致，不重复结算。
15. 日末拒绝新开仓、以最后有效 C 结算残仓，下一日空仓；信号退出与日末退出分开标记。
16. 每日、方向及全区间收益以虚拟盈亏除以相应名义投入计算；无投入时收益率为 null；不得算术叠加各笔收益率。
17. 同柱开平冲突、多个到期卖出候选、无仓卖出及不同发起分钟的到期买入候选具有确定性且可审计的结果。

## 12. 已确认的首期范围

- 当前柱采用只替换 close 的 H/L/C 三分支。
- 同动作同分钟只登记一个候选，固定 H → L → C 优先级；其他分支命中写入审计。
- 延迟柱数采用 `max(1, ceil(delaySeconds / 60))`。
- 第一阶段包括信号、候选、延迟登记、验证和监控标的参考收益统计。
- 决策柱收盘价记账；同方向等额名义资金逐次加仓；卖出信号平掉同侧全部虚拟仓位；每日收盘统一结算。
- 不模拟具体牛熊证收益、券商订单撮合或自动寻标。

## 14. 监控标的参考收益设计

### 14.1 已确认的记账规则

- 立即信号：触发柱 C 作为开平仓参考价。
- 延迟信号：验证通过柱 C 作为开平仓参考价，不回填到发起柱。
- 每次开仓投入固定名义资金 N，默认标准化为 1；虚拟数量 q = N / entryPrice，允许分数数量，不使用整手限制。
- 同方向允许逐次加仓，每次形成独立批次。不增加未请求的固定总资金或加仓上限。
- SELLCALL 结算所有未平多头批次，SELLPUT 结算所有未平空头批次；不自动反手，不套用生产智能平仓选单。
- 多空各自保留批次，允许并存；空头是方向性虚拟敞口，不依赖真实融券权限，也不把卖空所得当成新增可投入本金。
- 每日最后一根有效分钟柱禁止新开仓；先按获准卖出动作退出，再按最后 C 对剩余批次统一日末结算；只做一次结算并区分退出原因。
- 次日空仓开始；指标窗口仍可以读取前一交易日，不把持仓生命周期与指标预热混为一谈。

### 14.2 单笔、每日和全区间公式

对于批次 j，方向 d 为多头 +1、空头 -1：

`r[j] = d * (exitPrice[j] - entryPrice[j]) / entryPrice[j]`

`pnl[j] = N[j] * r[j]`

任意统计集合 S（单日、多头、空头或全部回测区间）：

`referenceReturn[S] = sum(pnl[j]) / sum(N[j])`

等额名义资金下，该结果等于集合内已结算批次收益率的算术平均。一个信号平掉多个批次时，每批分别结算；平仓事件数和批次数分开统计。日末全平保证完整交易日的全部投入都有终值。

例如：两笔多头分别在 100、110 开仓，各投入 N=1，在 120 一起平仓：

- 第一笔：20%；第二笔：约 9.0909%。
- 虚拟盈亏合计约 0.290909；投入合计 2。
- 当日参考收益约 14.5455%，不是 29.0909%。

无开仓的集合收益率为 null，投入及盈亏为 0。全区间按各日投入加权，不能平均每日收益率，更不能简单连乘。本口径衡量累计投入名义资金上的方向收益，不是固定本金账户回报；同一名义单位重复使用的各次开仓仍分别计入投入。

### 14.3 同柱冲突与授权的设计约定

以下为保证确定性采用的初步设计约定，不代表已观察到真实盘中顺序：

1. 新候选的 SELL 初始授权读取柱前持仓快照，指标条件原始命中可独立审计。
2. 先完成全部到期候选的验证和当前新候选评估，再处理本柱获准动作。
3. 同柱同方向开仓和平仓同时获准时，采用退出优先：结算已有仓位并跳过该柱同方向开仓，记录冲突原因。不靠 H/L 的计算顺序推断成交顺序。
4. 多个卖出候选同柱通过，持仓只结算一次；其余记录无剩余持仓，不重复计算收益。
5. 不同发起分钟的买入候选若在同柱通过，各自保持身份并可各加一笔；同一候选不能重复记账。同一发起分钟同一动作仍只登记一个候选。
6. 日末结算优先级高于任何新开仓。正常日末缺失最终应有数据时，将该日标记不完整，不静默提前平仓并冒充完整日结果；实际无成交柱与采集缺口按数据校验策略区分。

### 14.4 结果边界

首期输出价格毛收益，不计手续费、滑点、借券费或融资费，报告明确披露。使用最终 H/L/V 试算及同柱 C 记账是假设性模型，不承诺可实现交易价格。

本次确认的分母为累计投入名义资金，而非固定初始账户本金。因此不输出账户资金曲线复利收益及账户百分比最大回撤；如未来需要此类指标，应另行明确初始资金、可用资金、敞口上限与融资规则，不能由参考收益曲线冒充。
